# Annotated Source Library

What each source teaches and when to consult it, as the source report lists them. Prefer the original transcript, recording, or post over a news summary. No row points at a retrievable passage: the report names blogs, books, and interview venues, not lines, so each row is where to look, not a citation. Details the report does not contain are tagged `[outside report]`.

| Source | What it teaches | Consult when |
|---|---|---|
| Nolan Bushnell, Guardian interview | Origin of "easy to learn, difficult to master"; fundamentals over gimmicks | Onboarding, difficulty curve, resisting engagement hacks |
| Frank Cifaldi, GDC recap of Blizzard's core design concepts (Rob Pardo) | Blizzard's restatement of easy/learn, player focus | Difficulty, accessibility, depth |
| Soren Johnson, Designer Notes blog | Interesting decisions, fun-per-time formula, interface tasks, players optimizing fun away (the report attributes that phrase to no one; crediting it to Johnson is common and `[outside report]`, as P11 says) | Strategy complexity, padding, dominant strategies |
| Sid Meier's Memoir! | Design diaries, spreadsheet prototyping, cutting features, the Colonization randomness lesson | Systems design, pillars, when to cut |
| Hunicke et al., MDA: A Formal Approach to Game Design (the report names Hunicke only; LeBlanc and Zabek as co-authors are `[outside report]`) | Mechanics to dynamics to aesthetics as a lens | Explaining why a mechanic produces a feeling; not a recipe |
| Raph Koster, A Theory of Fun for Game Design | Fun as pattern-learning; mastery then grind | Justifying challenge, diagnosing grind |
| Csikszentmihalyi, Flow | Challenge matched to skill | Difficulty ramps, pacing, boredom vs anxiety |
| Steve Swink, Game Feel | Control parameters, responsiveness, juice | Core movement, input tuning, feedback |
| Jonathan Blow, GDC Vault talks | Iterative design, one core idea, teaching through mechanics | Concept focus, tutorialization |
| GDC postmortems (various) | Small feel tweaks with large effects; what teams cut and why | Prototyping, scope, polish |
| Edge Magazine interviews with Miyamoto | Prototyping habits, playfulness, core-first | Core feel, prototyping |
| Kotaku interviews with Miyazaki | Level-first design, learning from deaths | Difficulty, level flow |
| Larian dev diaries (Swen Vincke) | Open development, documentation, community balancing | Bible practice, alpha testing |
| Wube blog on Factorio (the Friday Facts name is `[outside report]`) | Telemetry, watching new players, loop-fit features | Progression, telemetry, feature gating |
| Stardew Valley dev blog and forum posts (Barone) | Solo scope, community feedback, shipping when good enough | Solo dev process, scope |
| Supergiant talks and interviews (Amir Rao) | Theme-first development, reactive status text added after playtests | Theme, feedback to the player |
| Academic work on motivation (self-determination theory) and player typologies (Bartle) | Competence, autonomy, relatedness; player types as a lens | Psychology context; use with caution, not as segmentation gospel |

Every entry in `PRINCIPLES.md` (next to this file) carries an Evidence line with one of three values. `studied`: rests on published research or theory the report names. `practiced`: rests on a developer's or studio's own account of how they work. `opinion`: a designer's or the report's stated view with neither behind it. When citing outside the catalog, carry the same marking and the `[outside report]` tag where it applies.
