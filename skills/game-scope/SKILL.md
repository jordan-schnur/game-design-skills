# Game Scope

Rank or cut features by pillar alignment and fun per development cost, and decide whether the project passes its current phase gate. Finish a simple game well. Call the Skill tool with "game-design-principles" and read the bible: without pillars, prioritization is taste.

## Output

1. **Phase and gate.** Which phase the project is in (concept, core prototype, expansion, systems, polish, launch prep, post-launch) and the gate question for leaving it. Gates: core loop fun in greybox; each added mechanic still serves a pillar; full loop playable end to end; experience tight and matches the vision; players outside the team enjoy it. State whether the gate is passed, with the evidence from the bible.
2. **Table.** One row per feature: the pillar it serves (or none), the decision it creates for the player, estimated cost (small / medium / large, in weeks for this team), whether it is table stakes for the audience (a missing one will be punished), whether it is visible in the trailer or demo, and the verdict: build, build small, defer, cut.
3. **Cuts, with reasons.** A cut names the pillar it fails or the cost it cannot justify. Post-launch is a legitimate home; say which cuts go there.
4. **What is missing.** Table-stakes work absent from the list: save robustness, onboarding for the first twenty minutes, settings, controller support where the audience expects it, store page and demo. Add them to the table.
5. **Calendar.** Build order with the polish tail protected: no new features in the final third of the time. What slips first if anything slips.
6. **Record.** Decisions for the bible, through the Skill tool with "game-bible".

## Rules the table enforces

- A feature serving no pillar and creating no decision is cut unless it is table stakes.
- Two systems competing for the same hours: the one closer to the hook wins.
- Late content additions are the most common self-inflicted wound. An addition in the last third needs a pillar, a tiny cost, and a reason it cannot wait.
- A wishlist count ("40 recipes") is not a design. Ask what the smallest number that gates progression is.

## Confidence

Say what would change the ranking: engine, what already exists, how the current moment-to-moment interaction feels.
